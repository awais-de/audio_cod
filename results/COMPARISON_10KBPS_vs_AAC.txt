================================================================================
ROOT CAUSE ANALYSIS
================================================================================

WHY IS BITRATE STILL ~88 kbps INSTEAD OF 10 kbps?

1. TRAINING OBJECTIVE MISMATCH:
   - Rate-distortion loss used L2 norm proxy: rate = ||z||_2 / sqrt(D)
   - L2 norm doesn't directly correlate with entropy-coded bitrate
   - Model minimized L2 norm, but entropy remained high

2. QUANTIZATION BOTTLENECK:
   - Using 1-bit quantization (0.48 bits/coefficient)
   - Latent dimensionality d_model=384 → 384 coeffs per frame
   - Frame rate: ~100 Hz (hop_length=160, sr=16000)
   - Theoretical bitrate: 384 × 0.48 × 100 = 18,432 bps ≈ 18 kbps
   - Actual: 88 kbps → suggests high temporal redundancy not compressed

3. MISSING TEMPORAL COMPRESSION:
   - Each frame encoded independently
   - No inter-frame prediction/delta coding
   - Redundant information across consecutive frames

4. ENTROPY CODING INEFFICIENCY:
   - QuantizedLatentCodec uses zlib compression on quantized values
   - If latent entropy is high (values appear random), zlib can't compress
   - Model may have learned high-entropy representations

================================================================================
RECOMMENDATIONS
================================================================================

1. INVESTIGATE L2 NORM vs ENTROPY:
   ✓ Already done: L2 norm proxy didn't reduce entropy
   → Need true entropy-based rate measurement during training

2. ANALYZE LATENT STATISTICS:
   - Measure actual entropy of quantized latents
   - Check if values are uniformly distributed (high entropy)
   - Visualize latent activation patterns

3. ALTERNATIVE APPROACHES:
   a) Use actual entropy model during training (fix dimension mismatch)
   b) Implement vector quantization (VQ-VAE style) with small codebook
   c) Add temporal prediction/delta encoding
   d) Use learned entropy model (e.g., autoregressive/hyperprior)

4. SIMPLER BASELINE:
   - Test with 2-bit or 4-bit quantization to verify compression path
   - Compare with offline entropy coding tool (e.g., arithmetic coding)

5. ARCHITECTURE CHANGES:
   - Reduce latent dimensionality (384 → 128 or 64)
   - Add bottleneck layer before quantization
   - Implement learned quantization (differentiable)

================================================================================
CONCLUSION
================================================================================

The 10 kbps-targeted rate-distortion model (phase3b_l2_10kbps) shows:
  ✓ Improved PESQ over previous phase3b (+24%)
  ✗ Still 7.4× higher bitrate than AAC
  ✗ Below AAC perceptual quality (PESQ: 1.50 vs 2.06)
  ✓ Better intelligibility than AAC (STOI: 0.50 vs 0.24)

The model did NOT achieve the 10 kbps target. The rate-distortion training
with L2 norm proxy successfully reduced distortion but failed to reduce the
actual entropy-coded bitrate.

NEXT STEPS:
1. Analyze why quantized latents have high entropy (88 kbps vs 18 kbps theoretical)
2. Implement true entropy-based rate loss or vector quantization
3. Consider temporal compression (delta coding, RNN-based prediction)
4. Evaluate if current architecture can achieve <20 kbps at acceptable quality

The current approach suggests that minimizing ||z||_2 does not guarantee
low entropy after quantization. A fundamental redesign of the rate control
mechanism is needed to achieve the 10 kbps target.
